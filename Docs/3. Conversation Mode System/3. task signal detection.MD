# Task Signal Detection

## Purpose

Task Signal Detection is a user experience feature that allows Purrfect to recognize when a conversation may benefit from entering Planner mode.

Its purpose is to make the interaction feel more natural by offering planning assistance when appropriate.

Task Signal Detection is intentionally **non-critical**.

The system never depends on perfect task detection because users can always explicitly request planning.

---

# Responsibility

Task Signal Detection has one responsibility only:

> Determine whether the current user message appears to describe a potential task.

It does **not**:

- Change conversation modes.
- Activate the Planner Agent.
- Start execution.
- Modify conversation state.
- Make workflow decisions.

Its only responsibility is reporting whether a task signal exists.

---

# Detection Flow

```text
User
    ↓
Chitchat Agent
    ↓
Task Signal Detection
    ↓
Structured Result
    ↓
Conversation Mode System
```

The Chitchat Agent performs task signal detection as part of its normal conversation workflow.

The Conversation Mode System decides what to do with the result.

---

# Structured Output

Task Signal Detection returns a simple structured result.

Example:

```json
{
  "task_signal": true
}
```

or

```json
{
  "task_signal": false
}
```

No confidence score is required.

No probability values are required.

The Conversation Mode System treats the result as a simple suggestion.

---

# Conversation Mode Interaction

Task Signal Detection never changes conversation mode directly.

Instead:

```text
Task Signal
        ↓
Conversation Mode System
        ↓
Determine whether Planner should be offered
        ↓
User confirmation
        ↓
Planner
```

The Conversation Mode System remains the only component allowed to perform conversation mode transitions.

---

# Design Philosophy

Task Signal Detection is intentionally lightweight.

It exists to improve user experience rather than control system behavior.

The architecture never depends on perfect intent recognition.

Instead:

- False positives are acceptable.
- False negatives are acceptable.

Worst-case scenarios are intentionally low risk:

False positive:

```text
User
    ↓
One unnecessary Planner offer
    ↓
User declines
    ↓
Continue Chitchat
```

False negative:

```text
Task not detected
    ↓
User explicitly requests planning
    ↓
Planner
```

Because explicit planning requests always remain available, imperfect task detection never blocks the user.

---

# Future Improvements

Future versions of Purrfect may improve task detection using:

- User behavior learning.
- Personalized preferences.
- Machine learning models.
- Better LLM reasoning.

These improvements should enhance detection quality without changing the surrounding architecture.

The Conversation Mode System remains deterministic regardless of how task detection evolves.

---

# Core Principles

- Task Signal Detection is a convenience feature.
- It never controls conversation mode.
- It never starts execution.
- It only reports whether a potential task signal exists.
- The Conversation Mode System decides whether Planner should be offered.
- Explicit user requests always take priority over inferred task signals.
