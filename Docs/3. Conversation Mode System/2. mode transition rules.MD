# Mode Transition Rules

## Design Principle

Conversation mode transitions are controlled exclusively by the Conversation Mode System.

Agents may **suggest** or **request** a transition, but they can never change the conversation mode directly.

---

# Chitchat → Planner

There is only **one** transition rule.

Every transition into Planner must pass through a **delegation confirmation gate**.

This applies to:

- Implicit task signals.
- Explicit planning requests.

Example:

```text
User
    ↓
Chitchat Agent
    ↓
Conversation Mode System
    ↓
"Would you like me to hand this over to the Planner Agent?"
    ↓
User confirms
    ↓
Planner
```

The confirmation is **not** asking whether the user wants planning.

Instead, it asks whether the user wants the current conversation delegated to the Planner Agent.

This keeps every transition consistent with the multi-agent architecture.

---

# Planner → Planner

Remain in Planner while:

- Gathering missing information.
- Building plans.
- Revising plans.
- Answering temporary unrelated questions.

Example:

```text
Planner

↓

User:
What's the weather tomorrow?

↓

Answer weather

↓

Return to Planner
```

Temporary conversations never terminate the planning session.

---

# Planner → Execution

Planner transitions to Execution only when:

- Required information has been collected.
- The plan has been validated.
- The user confirms execution.

Execution never starts automatically.

---

# Execution → Planner

Execution returns to Planner when:

- Additional information is required.
- User confirmation is required.
- Recoverable validation failures occur.

Planner continues refining the active task.

---

# Execution → Chitchat

Execution completes successfully.

Flow:

```text
Execution
    ↓
Clear active_task_id
    ↓
Return to Chitchat
```

---

# Planner → Chitchat

Planner exits when:

- User cancels planning.
- User declines execution.
- Planning is abandoned.

The active planning task is cleared.

Historical tasks remain in the Memory System.

---

# Invalid Transitions

The following transitions should never occur.

```text
Chitchat
    │
    └──► Execution ❌

Execution
    │
    └──► Execution ❌

Execution
    │
    └──► Chitchat
          without completion ❌
```

---

# Core Transition Principle

- Only the Conversation Mode System may change conversation modes.
- Agents never change modes directly.
- Planner activation always requires explicit user confirmation through the delegation gate.
- The user interacts with agents, not implementation details such as "conversation modes."
