# Conversation Mode State

## Purpose

The Conversation Mode System maintains the current high-level conversational state. It determines whether Purrfect is having a normal conversation or actively organizing a user task.

Conversation Mode is intentionally lightweight. It is **not** responsible for storing task data, execution history, or long-term memory.

---

# Conversation Modes

## Chitchat

Default conversation mode.

### Responsibilities

- Hold natural conversations with the user.
- Answer questions.
- Detect potential task signals.
- Offer transition into Planner mode when appropriate.

The Chitchat Agent **cannot** directly switch conversation modes. It only reports task signals to the Conversation Mode System.

---

## Planner / Organizer

Activated only after:

- Explicit user confirmation.
- Explicit planning requests.

### Responsibilities

- Gather missing information.
- Maintain the active planning session.
- Build and refine execution plans.
- Hand validated plans to the Execution Layer.

Planner owns the current active task.

---

## Execution

Execution is **not** a conversation mode.

Once a plan is confirmed:

```text
Planner
    ↓
Execution Layer
    ↓
Planner (more information required)

or

Chitchat (execution completed)
```

---

# Conversation State

The Conversation Mode System maintains only lightweight conversation state.

```text
Conversation State
├── mode
│   ├── chitchat
│   └── planner
│
├── active_task_id
│   └── Present only while Planner is active
│
├── conversation_topic
│   └── High-level conversation topic
│
├── planner_prompt_declined
│   └── Suppresses repeated planner offers
│
└── topic_refresh_ttl
    └── Remaining turns before topic re-evaluation
```

---

# State Responsibilities

## mode

Represents the current conversation mode.

---

## active_task_id

References the active planning task.

Created when entering Planner.

Cleared when:

- Planning is canceled.
- Execution completes.
- Planning is abandoned.

Historical tasks belong to the Memory System.

---

## conversation_topic

Represents the current high-level conversation theme.

Examples:

- Travel
- Shopping
- Career
- Programming
- Health

The topic represents the overall discussion rather than the current message.

It remains stable across multiple conversation turns and is **not** recalculated every user message.

Instead, the topic is periodically re-evaluated after a configurable number of user turns.

---

## planner_prompt_declined

Indicates that the user declined entering Planner mode.

Purpose:

Prevent repeatedly asking:

> "Would you like me to help plan that?"

during the same conversation.

This suppresses automatic planner suggestions only.

It **never** blocks explicit planning requests from the user.

---

## topic_refresh_ttl

Represents the remaining user turns before the conversation topic is allowed to be re-evaluated.

The purpose is to avoid unnecessary topic changes caused by normal conversational drift.

The refresh interval should be configurable.

Recommended default:

```text
10–20 user turns
```

---

# Design Principles

- Conversation Mode manages conversation flow only.
- Planner owns active task state.
- Task history belongs to the Memory System.
- Execution is handled outside Conversation Mode.
- Explicit user requests always override automatic planner suppression.
- Task signal detection exists to improve user experience rather than control system behavior.
- Future ML systems may personalize planner suggestions, but deterministic Conversation Mode remains the system foundation.
