# Behavior When User Changes Topic During Planning

## Purpose

This document defines how Purrfect handles temporary topic changes while an active planning workflow is in progress.

The goal is to maintain natural conversation without accidentally losing or canceling the user's active planning task.

---

# Core Rule

A topic change during Planner mode does not automatically cancel the active planning state.

The active task remains unless:

- The user cancels planning.
- The task completes.
- The workflow reaches a terminal state.

---

# Temporary Topic Changes

Users may ask unrelated questions while planning.

Example:

```text
Planner:
Let's continue preparing your Japan trip plan.

User:
Before that, what's the weather tomorrow?
```

Behavior:

```text
Planner
    ↓
Handle temporary question
    ↓
Return to active planning task
```

The system should answer naturally without forcing the user to return to planning immediately.

---

# Active Task Preservation

During temporary topic changes:

Preserve:

- active_task_id
- collected_information
- missing_information
- current_plan

Do not:

- Create a new task.
- Cancel the current task.
- Reset Planner state.

---

# Returning to Planning

After answering a temporary question, Purrfect should naturally continue the active planning workflow when appropriate.

Example:

```text
User:
What's the weather tomorrow?

Planner:
Tomorrow looks clear.

For your Japan trip, we still need your hotel preference.
```

The transition back should feel conversational, not like switching systems.

---

# Actual Topic Change

A user may intentionally abandon the current planning topic.

Example:

```text
User:
Actually, let's forget the Japan trip and plan my home renovation instead.
```

Behavior:

```text
Detect new planning objective
        ↓
Ask for Planner transition handling
        ↓
Cancel or replace active task if confirmed
```

The system should not silently overwrite an active task.

---

# Cancellation

Explicit cancellation ends the active planning workflow.

Example:

```text
User:
Never mind, cancel this plan.
```

Flow:

```text
Planner
    ↓
Cancel active task
    ↓
Clear active_task_id
    ↓
Return Chitchat
```

---

# Design Principles

- Temporary topic changes do not destroy active planning state.
- Planner should support natural conversation.
- Active tasks are only changed intentionally.
- Memory stores historical tasks after completion or cancellation.
- Users remain in control of replacing or abandoning planning workflows.
